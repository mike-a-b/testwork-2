**Запросы для создания таблиц:**

```jsx
CREATE TABLE `info` (
        `id` int(11) NOT NULL auto_increment,
       `name` varchar(255) default NULL,
        `desc` text default NULL,
        PRIMARY KEY (`id`)
) ENGINE=MyISAM DEFAULT CHARSET=cp1251;

CREATE TABLE `data` (
        `id` int(11) NOT NULL auto_increment,
        `date` date default NULL,
        `value` INT(11) default NULL,
        PRIMARY KEY (`id`)
) ENGINE=MyISAM DEFAULT CHARSET=cp1251;

CREATE TABLE `link` (
        `data_id` int(11) NOT NULL,
        `info_id` int(11) NOT NULL
) ENGINE=MyISAM DEFAULT CHARSET=cp1251;
```

**Варианты оптимизации:**
1. Проблемы - здесь
   - 1.1. В запросе используется 3 таблицы, которые не имеют индексов. Link - это таблица связи, которая не имеет первичного ключа. В ней должны быть индексы на поля info_id и data_id.'. 
   - Link таблица. Она здесь используется, предположительно, как pivot таблица для связи many-to-many между таблицами info и data.
   - 1.2. Запрос выполняется медленно.
   - 1.3. Запрос возвращает много ненужных данных.
   - Тип MySQL - MyISAM. Он не поддерживает транзакции и внешние ключи, что может привести к проблемам с целостностью данных.
   - 1.4. В таблице info поле name имеет тип varchar(255), что может быть избыточным, если имена не превышают 50 символов.
   - 1.5. В таблицах используются имена, которые используют зарезервированные слова MySQL, такие, как "desc", "date". Это может привести к путанице и проблемам с совместимостью.
**Решение - здесь**
   - 1.1. Изменить тип таблиц на InnoDB, чтобы использовать транзакции и внешние ключи.
   - 1.2. Добавить индексы на поля info_id и data_id в таблице link.
   - 1.3. Удалить ненужные поля из запроса, чтобы уменьшить объем данных, которые возвращаются.
   - 1.4. Изменить тип поля name в таблице info на varchar(50).
   - 1.5. Переименовать поля "desc" и "date" в таблицах info и data соответственно, чтобы избежать путаницы с зарезервированными словами MySQL.
   - 1.7. Изменить тип кодировки на utf8mb4, чтобы поддерживать все символы Unicode.
